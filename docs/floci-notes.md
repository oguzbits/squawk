# Floci notes

Observed behaviour of the local AWS emulator, verified with a spike at the start of each milestone.
Versions: Floci server `2.3.0` (`floci/floci:2.3.0`), CLI `0.4.0`.

## General

| Topic                  | Observation                                                                                                                                                 | Consequence                                                                                                |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Startup                | Ready in well under a second; `GET /_floci/health` returns 200 once ready (also used by `floci doctor`).                                                    | `scripts/bootstrap-local.ts` polls this endpoint.                                                          |
| `floci start`          | Publishes only port 4566. There is no option for additional port mappings.                                                                                  | Floci is started via `docker-compose.yml` instead ([ADR 0001](adr/0001-run-floci-with-docker-compose.md)). |
| CLI compatibility      | `floci doctor`, `floci status`, `floci env` and `floci logs` work against the compose container because it is named `floci`.                                | The CLI stays usable for diagnostics.                                                                      |
| Storage                | Default storage mode is in-memory. All resources are gone after a restart.                                                                                  | Bootstrap is idempotent and runs on every `pnpm env:up`.                                                   |
| IAM                    | Policies are not enforced by default (log: `policy enforcement disabled`). Enforcement can be turned on with `FLOCI_SERVICES_IAM_ENFORCEMENT_ENABLED=true`. | Still to be evaluated once IAM roles exist. Policies are written least-privilege regardless.               |
| AWS SDK for JavaScript | Reads `AWS_REGION`, not `AWS_DEFAULT_REGION` (which is what `floci env` prints).                                                                            | `.env.example` sets `AWS_REGION`.                                                                          |

## RDS (PostgreSQL)

| Topic            | Observation                                                                                                                                                                                                                                                                                                           | Consequence                                                                                   |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Engine           | `CreateDBInstance` starts a real `postgres:16-alpine` container (PostgreSQL 16.15) through the mounted Docker socket. Status is `available` after ~1.5 s.                                                                                                                                                             | Real Postgres behaviour, including `EXPLAIN ANALYZE`.                                         |
| Networking       | Floci runs an auth proxy per instance on ports `7001+` inside the Floci container, assigned in creation order.                                                                                                                                                                                                        | Ports `7001-7005` are published on `127.0.0.1`.                                               |
| Endpoint address | `DescribeDBInstances` reports the Floci container IP (e.g. `172.23.0.2:7001`), which is not reachable from the host. `FLOCI_HOSTNAME` does not change this.                                                                                                                                                           | The app takes `DATABASE_URL` from configuration; bootstrap only checks that the port matches. |
| TLS              | The proxy generates a CA at `/app/data/tls/rds-ca.crt` inside the container.                                                                                                                                                                                                                                          | Not used locally; connections use plain TCP on `127.0.0.1`.                                   |
| Cleanup          | Floci starts its own containers next to itself (`floci-aws-rds-db-*`, and `floci-aws-ui` once the web console was opened). They are not part of the compose project: `docker rm -f floci` leaves the database orphaned, and a left-over `floci-aws-ui` keeps the compose network in use (`Resource is still in use`). | `pnpm env:down` removes all `floci-aws*` containers before `docker compose down`.             |

## S3

| Topic                 | Observation                                                                                                                                                                                    | Consequence                                                                                                                                                                                                                     |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Addressing            | Path-style addressing works (`http://localhost:4566/<bucket>/<key>`).                                                                                                                          | The S3 client sets `forcePathStyle` when `AWS_ENDPOINT_URL` is set.                                                                                                                                                             |
| Presigned POST policy | Floci evaluates the policy: `content-length-range` (too large and empty uploads answer 400), exact-match fields such as `Content-Type` (403) and the object key (403).                         | Upload limits are covered by integration tests against Floci.                                                                                                                                                                   |
| Signatures            | Not verified. A POST without `X-Amz-Signature` is accepted (204), and a presigned PUT URL with a replaced signature is not rejected for that reason.                                           | Signature handling cannot be tested locally. The policy conditions are what the tests rely on.                                                                                                                                  |
| CORS                  | Bucket CORS rules are stored and evaluated. The preflight answers 200 with the allowed origin and methods, and 403 for any other origin. Actual responses carry `Access-Control-Allow-Origin`. | The bucket CORS rule is created by the bootstrap script. Verified in Chrome: a cross-origin POST from `http://localhost:5173` succeeds, the same request from `http://[::1]:5173` fails with a network error (blocked by CORS). |
| Presigned PUT         | With AWS SDK v3 defaults, a presigned PUT upload answered 400 `BadDigest` (CRC32 mismatch). Not investigated further.                                                                          | Uploads use presigned POST ([ADR 0005](adr/0005-presigned-post-instead-of-upload-through-api.md)).                                                                                                                              |
| Policy fields         | `createPresignedPost` turns every entry of `Fields` into an exact-match condition, so an additional `eq` condition for the same field is redundant.                                            | Only `Fields` and `content-length-range` are set.                                                                                                                                                                               |

## SQS, Lambda and S3 notifications

| Topic              | Observation                                                                                                                                                                       | Consequence                                                                               |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| Lambda execution   | `CreateFunction` (nodejs22.x, zip) runs the function in a sibling container from `public.ecr.aws/lambda/nodejs:22`. The first invocation pulls the image and is slow.             | Integration tests allow a long first invocation. The image is pulled by `pnpm env:up`.    |
| SQS event source   | An event source mapping polls the queue about once per second and invokes the function with the SQS event.                                                                        | The import runs end to end locally.                                                       |
| Mapping cleanup    | `DeleteFunction` does not delete its event source mapping. The poller logs `function not found` every second until the mapping is deleted.                                        | Bootstrap and tests delete the mapping before the function.                               |
| Dead-letter queue  | With a `RedrivePolicy` (`maxReceiveCount: 2`, `VisibilityTimeout: 3`) a message whose Lambda invocation throws lands in the DLQ after about 6 s.                                  | Redrive is covered by an integration test.                                                |
| S3 notifications   | `PutBucketNotificationConfiguration` to an SQS queue works. The queue first receives an `s3:TestEvent`, then the `ObjectCreated:Put` record (as on AWS).                          | The consumer must ignore messages without `Records`.                                      |
| Lambda to database | From inside a Lambda container the RDS proxy answers on `floci:7001` and `host.docker.internal:7001`. `AWS_ENDPOINT_URL` inside the function is `http://localhost.floci.io:4566`. | The function takes `DATABASE_URL` from its environment, set to `floci:7001` by bootstrap. |
| Bundling           | A Lambda bundle in ESM format fails at init with `Dynamic require of "node:https" is not supported` when CommonJS dependencies (AWS SDK, `pg`) are bundled.                       | The esbuild banner defines `require` through `createRequire`.                             |
